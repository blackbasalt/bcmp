# Сборка CSS отдельной Node-стадией в Dockerfile

Интерфейс строится на Tailwind + daisyUI, которым нужен шаг сборки, а рабочий образ —
`python:3.13-slim` с uv и без Node. Мы добавляем в `Dockerfile` отдельную стадию на
`node`, которая собирает CSS, и копируем только результат в Python-стадию: рантайм
остаётся без Node, а сборка воспроизводима в CI.

## Рассмотренные варианты

- **Готовый `static/css/app.css` в репозитории** — деплой не меняется вовсе, но
  собранный артефакт лежит в git, а забытая пересборка ничего не ломает явно: страница
  просто выглядит неправильно у того, кто обновил шаблоны.
- **Standalone-бинарник Tailwind CLI** — обходится без Node, но подключение плагина
  daisyUI в таком режиме требует ручного размещения файлов плагина и завязано на то,
  как именно версия CLI их разрешает.
- **CDN** — Tailwind прямо не рекомендует свой CDN-вариант для продакшена, а мы
  разворачиваемся на VPS за nginx.

## Последствия

- Появление Node в проекте, где его больше нигде нет, выглядит неожиданно — он
  существует только на время сборки образа и в рантайм не попадает.
- Требует рабочего `collectstatic`, то есть заданного `STATIC_ROOT` в настройках
  (сейчас закомментирован, из-за чего контейнер не стартует).
